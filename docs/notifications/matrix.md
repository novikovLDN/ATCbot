# Уведомления пользователю: пробный / платная / закончилась — матрица по коду

Ветка `fix/prod-followups` (= прод `main` 704c152e + доработки), проверено по коду 2026-09-14. Правка
параллельного агента (`get_active_paid_subscription` не считает bypass-only строку платной; «пробный
завершён» для строки, уже ставшей bypass-only; traffic_monitor — один поток из панели вместо GET на
юзера, логика порогов не менялась; `extend_remnawave_for_bypass` — в работе) принята как целевое поведение.

**Важно для понимания:** в `subscriptions` **одна строка на пользователя** (`telegram_id UNIQUE`,
`ON CONFLICT (telegram_id)`). «Тип» подписки = поле `source` этой строки: `trial`, `payment`,
`auto_renew`, `gift`, `admin`, `game_strike`/`game_dice`, `bypass_only`. Какие уведомления получит
человек, решает именно `source` (+ `admin_grant_days`, `users.trial_expires_at`). Любая выдача через
`grant_access` **перезаписывает `source`** (кроме подарочного «пробного ключа» на платной — N-07).

Воркеры: `trial_notifications` (5 мин), `reminders` (45 мин), `fast_expiry_cleanup` (1 мин),
`auto_renewal` (10 мин, окно 6 ч), `traffic_monitor` (5 мин) — `main.py:136-152`.

### E. Воронка продаж (одобрено владельцем 2026-09-14, `docs/audit/SCOPE.md`)

Отдельный воркер `app/workers/sales_funnel.py` (раз в 5 мин, пачка ≤ 200 на цепочку) → логика
`app/services/sales_funnel/service.py` → состояние `database/funnel.py`, таблица `funnel_messages`
(миграция `090_sales_funnel.sql`). Существующие воркеры не менялись: шаг «сразу» цепочек 2 и 3 шлют они
(A6 −30 % 7 дн., C1/C2 −15 % 72 ч), воронка определяет события **только по состоянию БД** и продолжает
со следующего шага.

| Цепочка | Кто в ней (по БД) | Точка отсчёта | Шаги |
|---|---|---|---|
| 1 `start` | прошёл /start (капча), `trial_used_at IS NULL`, ни одной строки `subscriptions`, ни одной оплаты | `users.created_at` | +1 ч пробный; +1 д пробный «что даёт VPN»; +3 д пробный **или** −20 % 48 ч; +7 д −25 % 72 ч «на первый месяц»; +30 д −30 % 7 дн. |
| 2 `trial` | пробный закончился, после начала пробного нет оплат, нет активного premium (bypass-only и пробный не в счёт) | `users.trial_expires_at` | (сразу −30 % 7 дн. — A6); +1 д «скидка ещё действует, осталось N дн.»; +6 д «скоро сгорит» (та же −30 %, тот же срок); +14 д −25 % 72 ч; +30 д −30 % 7 дн.; +90 д −40 % 7 дн. |
| 3 `paid` | хотя бы раз платил (история: purchase / renewal / auto_renew), нет активного premium, после окончания нет оплат | `max(subscription_history.end_date)` (строка bypass-only хранит +10 лет, история — реальный конец) | (сразу −15 % 72 ч — C1/C2); +6 ч напоминание (та же −15 %); +1 д «осталось N дн.»; +3 д −20 % 72 ч; +7 д −25 % 72 ч; +30 д −30 % 7 дн.; +90 д −40 % 7 дн. |

**Правила (все проверяются в одной транзакции `claim` прямо перед отправкой):**
- Покупка или активация пробного → цепочка остановлена (правило цепочки перечитывается для этого пользователя и этого события).
- Только события **после** запуска: `app_settings.sales_funnel_started_at` пишет первый проход воркера; раньше — никогда (старая база — разовая рассылка по сегментам, ниже).
- ≤ 1 сообщение воронки в день (календарный день МСК); не раньше 6 ч после другого уведомления жизненного цикла (`automated_notification_sends`).
- Отправка только 10:00–21:00 МСК; вне окна шаг ждёт. Если пропущено несколько шагов — уходит последний наступивший, ранние помечаются `skipped`.
- `is_reachable = FALSE` не шлём; темп ≤ 25 сообщений/с (`broadcast_sender._Pacer`); `safe_send_message`; соединение БД на время отправки не держится.
- Дубль невозможен: `UNIQUE (telegram_id, chain, anchor_at, step)`, захват → отправка (рестарт между ними = сообщение потеряно, не задвоено).
- Скидка — существующая персональная (`user_discounts`) с точным сроком, выдаётся при отправке, `keep_max`: большая действующая не снижается, **равная не продлевается**. В тексте — то, что применит оплата (наибольшая из −15 % окна и персональной, как в `calculate_final_price`), и срок в МСК. Шаги «ещё действует» не создают новую скидку: срок фиксирован от события (пробный +7 дн., платная +72 ч); если скидки нет — выдаётся с этим же сроком, если срок почти вышел — шаг пропускается.
- Кнопка «Купить со скидкой» / «Продлить со скидкой» (`funnel_buy:<цепочка>`, `app/handlers/callbacks/funnel.py`) только показывает действующую скидку и открывает экран тарифов; скидку не создаёт и не продлевает. У цепочки 1 — ещё «Попробовать бесплатно» (`activate_trial`).
- Тексты: i18n `funnel.*` (RU + EN), в дашборде «Автоуведомления → 🔔 Напоминания», 16 ключей «Воронка · …»; выключенный шаг пропускается, цепочка идёт дальше. Переменные: `{percent}`, `{deadline}`, `{days_left}`.

**Старая база (до запуска воронки) — одна рассылка из дашборда.** Сегменты «Воронка — старая база» в
мастере рассылок (с числом получателей): `funnel_start_no_trial`, `funnel_trial_ended_no_purchase`,
`funnel_paid_ended_no_renewal` — те же правила, но событие **до** `sales_funnel_started_at`; недоступные
отфильтрованы. Кнопка «Купить со скидкой» (`promo_buy`) + процент и часы в мастере; темп рассылки 25/с.

## 2. Правила жизненного цикла (как бот обязан себя вести)

1. У человека одна подписка. Её **тип** решает, какие сообщения идут: **пробный** → только пробные; **платная** (покупка, автопродление, подарок) → только платные; **бесплатные дни** (админ, промо, игра без подписки) → «бесплатный доступ»; **только ГБ** → только сообщения о трафике.
2. **Купил во время пробного** → пробный закончился в эту секунду. Никаких пробных напоминаний и «пробный завершён». Первое сообщение — «подписка оформлена», дальше платные напоминания к новому сроку.
3. **Дни поверх подписки** (админ, игра, промо, подарочный ключ) только сдвигают дату и **не меняют тип**. Платная остаётся платной, пробный остаётся пробным (напоминания — к новой дате).
4. Каждое напоминание — **один раз за период**. Любое продление = новый период, флаги сбрасываются. Перед отправкой — проверка, что дата не изменилась.
5. **Автопродление**: включено и баланса хватает → «спишем N ₽ ДД.ММ», а не «продлите». Не хватает → «пополните на N ₽ до ДД.ММ ЧЧ:ММ МСК», и после пополнения — ещё одна попытка. Продлилось → «продлено, до ДД.ММ».
6. **Окончание — одно сообщение.** Платная → «подписка закончилась»; пробный → «пробный закончился». Если осталось **больше 0 ГБ** обхода — в том же сообщении «обход работает на оставшихся N ГБ», иначе «VPN отключён».
7. **−15 %**: одно окно на 72 ч за период. Открывает напоминание за 3 ч или само окончание — что раньше. Не продлевается. В тексте — точная дата и время МСК. Окна нет — в тексте нет скидки.
8. **Трафик**: одно сообщение на текущий порог, без каскада. «Трафик закончился» — с текстом по факту: premium есть → «основные серверы работают», premium нет → «доступ отключён».
9. Сообщение уходит **после коммита**, без удерживаемого соединения. При временной ошибке Telegram — повтор, при блокировке — пропуск.
10. Все даты в текстах — **МСК**.

## 3. Проблемы (❌ / ⚠️): сценарий и минимальная правка

**❌ #1 — Конец пробного = два сообщения и две разные скидки.**
Сценарий: пробный закончился в 12:00. `fast_expiry` переводит строку в bypass-only и отправляет (а) «Основная подписка закончилась, обход работает, ГБ на месте, −15 % до …» и (б) «Пробный доступ завершён, скидка 30 % на 7 дней». То же в пути `trial_notifications`.
Где: `fast_expiry_cleanup.py:327, 338, 396-405`; `trial_notifications.py:843-868`.
Правка: для `source='trial'` не ставить `expired_notice_pending` / не слать `traffic.subscription_expired_bypass_active`. Остаётся одно `trial.expired`, при работающем обходе — со строкой про ГБ.

**❌ #2 — «Обход работает, ГБ на месте» при 0 ГБ.**
Сценарий: платный Basic израсходовал 10 ГБ, подписка закончилась. Есть сущность в панели → C1 «ГБ на месте», хотя их нет и VPN не работает.
Где: `fast_expiry_cleanup.py:295-327`; `database/subscriptions.py:250-286`; `trial_notifications.py:819-858`.
Правка: после коммита (без транзакции) прочитать остаток в панели. > 0 → текущий текст; 0 → `subscription.expired_paid` + кнопка «Купить ГБ».

**❌ #3 — Дни от админа / промо поверх платной отключают все платные напоминания.**
Сценарий: подписка до 20.10, админ дарит +7 дней. Где: `database/subscriptions.py:1446-1488, 1540-1545`; `app/services/notifications/service.py:177-179`.
Правка: (1) в ветке продления `grant_access` выдача дней (`admin`, `game_*`) сохраняет текущий `source`, если строка `payment` / `auto_renew` / `gift` / `trial` — расширить правило N-07 (`:1446-1459`). (2) `is_admin_grant = admin_grant_days is not None` без `last_action_type`.

**❌ #4 — Дни во время пробного ломают пробный сценарий.**

### Что работает правильно (✅, коротко)
- Пробный и платные не дублируют друг друга: `reminders` пропускает `source='trial'`.
- Покупка во время пробного останавливает все пробные сообщения; «пробный завершён» не приходит.
- Все флаги платных напоминаний сбрасываются при любом продлении; следующий период получает напоминания заново.
- Окно −15 % — одно на период, 72 ч, не продлевается, дата и время в МСК, при окончании не открывается второй раз.
- «Подписка закончилась» — ровно один раз (UPDATE совпадает один раз), после коммита. Оплаченная подписка без обхода больше не заканчивается молча.
- Автопродление: успех и срыв списания сообщаются после коммита, один раз; кэшбэк рефереру — о каждом начислении.
- Bypass-only не получает напоминаний о premium.
- Правка соседа: пробный, закрытый ленивым путём или покупкой ГБ сразу после конца, теперь получает «пробный завершён».
