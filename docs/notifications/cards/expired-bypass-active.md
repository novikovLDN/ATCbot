# Истекла (есть обход): «Ваша основная подписка закончилась, обход работает»

[← к оглавлению](../README.md) · вердикт: ⚠️

| | |
|---|---|
| Ключ | i18n `traffic.subscription_expired_bypass_active` (без реестра) |
| Сегмент | платная **или** триальная подписка истекла, у пользователя есть bypass-сущность (`remnawave_uuid`) |
| Когда | ≤60 с после `expires_at` (fast_expiry) либо ≤5 мин (trial_notifications, если успел первым) |
| Воркер | fast_expiry_cleanup (60 с) · trial_notifications (5 мин) |
| Дедупликация | переход состояния: `source='bypass_only'`, `uuid=NULL`; флага нет |

## Назначение
Де-факто единственное уведомление «подписка закончилась». Сообщает, что обход продолжает работать, и предлагает купить трафик или подписку.

## Сегмент
Любая активная строка с `uuid IS NOT NULL` и `expires_at < now`, если у пользователя есть `remnawave_uuid`. Пользователи без обхода **ничего не получают** (`fast_expiry_cleanup.py:308-316`, [N-12](../bugs-and-risks.md#n-12)).

## Триггер и окно
- **fast_expiry:** выборка `fast_expiry_cleanup.py:163-173` → повторная проверка в транзакции (`:246-260`) → `has_remnawave` (`:264-267`) → `UPDATE … source='bypass_only', expires_at=+10 лет` (`:273-283`) → при `UPDATE 1` продление bypass в панели и отправка (`:284-307`). Активная платная подписка — пропуск (`:201-212`).
- **trial_notifications:** `trial_notifications.py:707-747` (только триал; см. [trial-expired](trial-expired.md)).

## Воркер и период
fast_expiry: 60 с (`fast_expiry_cleanup.py:42-44`), стартовый джиттер 5–60 с, лимит 15 с на батч (`:36, 182-184`), таймаут 120 с (`:393`).

## Источник данных
Только БД (`subscriptions.expires_at`). `expireAt` в панели Remnawave не сверяется. Если синхронизация продления с панелью упала (`auto_renewal.py:386-394` — только лог), VPN отключится по панели раньше, а бот ничего не скажет ([R-14](../recommendations.md#r-14)).

## Фильтр получателей
- fast_expiry: **без** `is_reachable` (сообщение уйдёт и «недоступным»; `safe_send_message` снова отметит их).
- trial_notifications: с `is_reachable` (`:831`).

## Текст
- RU (`app/i18n/ru.py:1127`):
  ```
  ⚠️ <b>Ваша основная подписка закончилась</b>

  Обход блокировок продолжает работать — ваши ГБ на месте.

  Не забудьте докупить трафик, если он заканчивается 👇
  ```
- EN (`app/i18n/en.py:826`): «⚠️ <b>Your main subscription has expired</b> … Bypass continues to work …» ✅
- Кнопки (`fast_expiry_cleanup.py:301-304`):
  - `traffic.buy_traffic_btn` «💳 Купить трафик» → `buy_traffic`;
  - `traffic.buy_subscription` «📈 Купить подписку» → `menu_buy_vpn`.

  Кнопки «продлить со скидкой» нет.

## Переопределение из дашборда
Нет; в `automated_notification_sends` не логируется.

## Дедупликация
Сам переход состояния: fast_expiry выбирает только `uuid IS NOT NULL`, а после перехода `uuid = NULL`. trial_notifications после перехода считает строку «платной» и выходит (`trial_notifications.py:655-663`). Между двумя воркерами дубля нет ✅.

## Риски задвоения
- ⚠️ Отправка **внутри** `conn.transaction()` (`fast_expiry_cleanup.py:244-307`), до записи аудита (`:323`). Откат после отправки (ошибка аудита, таймаут 120 с) → строка остаётся `active` → повтор через минуту ([N-11](../bugs-and-risks.md#n-11)).
- ⚠️ При продлении такой строки `grant_access` идёт по ветке новой выдачи (`uuid` NULL). При следующем истечении переход и сообщение повторятся — это корректно, новый период.

## Риски потери
- ⚠️ Отправка через `safe_send_message` без повтора: временная ошибка — потеря (переход уже закоммичен).
- ❌ Пользователи без обхода — полная тишина ([N-12](../bugs-and-risks.md#n-12)).

## Вердикт
⚠️ **Риск.** Работает для пользователей с обходом. Дубль возможен при откате, у пользователей без обхода уведомления нет.
