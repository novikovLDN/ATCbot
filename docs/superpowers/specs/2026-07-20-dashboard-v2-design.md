# Дашборд ATCbot v2 — дизайн-система и редизайн

Дата: 2026-07-20
Статус: на утверждении

## Задача

Полный редизайн админ-дашборда под эстетику 2026–2027, ощущение
«технологично и дорого», плюс максимальное расширение функциональности
экрана «Пользователи» и проверка корректности существующих функций.

## Исходное противоречие и как оно разрешено

Запрос звучал как «много анимаций, очень красиво, супер дорого».
Исследование трендов 2026–2027 (15 поисковых запросов, разбор
first-party источников Raycast / Linear / Motion / Emil Kowalski)
дало прямо противоположный вывод для этого класса продуктов:

> Эстетика Awwwards-агентств оптимизирована под первые 40 секунд.
> Админ-панель оптимизируется под 8 часов.

Ощущение «дорого» в рабочем инструменте создаётся **точностью статики**,
а не количеством движения: перцептивно ровной цветовой лестницей,
волосяными границами, выровненными цифрами, мгновенным откликом на
клавиатуру. У Raycast в дизайн-системе **нет теней вообще** — и это
читается дороже, чем свечение на каждой карточке.

Три техники, которые изначально предполагались, исключены с обоснованием:

| Техника | Почему исключена |
|---|---|
| Kinetic typography | «Почти никогда не доезжает до продакшена». Конфликт со скринридерами, layout shift ломает Core Web Vitals. |
| Глассморфизм на скроллящихся карточках | `backdrop-filter` даёт **−15…30% FPS на среднебюджетных Android**. У продукта PWA и важная мобильная версия. Допустим точечно на навбаре и модалках поверх контролируемого фона. |
| Анимация автообновляемых чисел | На Обзоре `refetchInterval: 60_000`. Анимация числа раз в минуту — мерцание в периферийном зрении оператора весь рабочий день. |
| WebGL / 3D | 800 КБ – 2 МБ рантайма ради эффекта, не несущего функции. |

Это по-прежнему **полный переворот стиля**: переписываются токены,
примитивы и все 17 экранов. Меняются средства, которыми набирается
«дорого».

## Решения, принятые заказчиком

1. **Акцент — лайм.** Бот-фронт уже несёт лаймовую айдентичность;
   дашборд возвращает её и продукт становится визуально цельным.
2. **Остаёмся на Tailwind v3.** OKLCH заводится через CSS-переменные как
   source of truth — вся польза от перцептивной однородности без
   миграции фреймворка. Container queries — плагином.
3. **Максимум функций** на экране «Пользователи»: подключаем всё, что
   позволяет бэкенд, включая новые эндпоинты.

## Часть 1. Дизайн-система v2

### 1.1 Цвет — OKLCH

OKLCH перцептивно однороден: равное изменение числа = равное изменение
восприятия. Поэтому лестница поверхностей с ровным шагом lightness
выглядит **визуально ровной**, чего невозможно добиться в HEX.
Поддержка ~96% на начало 2026 (Chrome/Edge 111+, Safari 15.4+,
Firefox 113+).

```css
:root {
  /* Лестница поверхностей. Шаг lightness ровно 0.027 — это и есть
     источник ощущения «сделано системно». Глубина берётся отсюда,
     а не из теней. */
  --canvas:      oklch(0.145 0 0);
  --surface-1:   oklch(0.172 0 0);
  --surface-2:   oklch(0.199 0 0);
  --surface-3:   oklch(0.226 0 0);
  --surface-4:   oklch(0.253 0 0);

  /* Границы — alpha, не hex: один токен читается корректно на канвасе,
     на карточке и внутри поповера. */
  --hairline:      oklch(1 0 0 / 0.08);
  --hairline-hi:   oklch(1 0 0 / 0.16);

  /* Текст. Потолок 0.97, не 1.0 — чистый белый на почти-чёрном
     даёт гало вокруг глифов на OLED. */
  --ink:    oklch(0.97 0 0);
  --body:   oklch(0.80 0 0);
  --mute:   oklch(0.63 0 0);
  --ash:    oklch(0.47 0 0);

  /* Единственный акцент. Всё остальное в интерфейсе — серое. */
  --accent:      oklch(0.90 0.19 122);
  --accent-dim:  oklch(0.90 0.19 122 / 0.14);

  /* Семантика: одинаковые L и C, меняется только H — цвета
     автоматически равновесны по восприятию. */
  --ok:    oklch(0.75 0.15 150);
  --warn:  oklch(0.75 0.15 85);
  --err:   oklch(0.75 0.15 25);
}
```

**Правило акцента.** Лайм появляется ровно в четырёх местах: активный
пункт навигации, главная линия на графике, фокус-кольцо, один primary
CTA на экране. Если на экране два лаймовых элемента конкурируют —
это ошибка, а не решение.

### 1.2 Глубина без теней

Все `box-shadow` удаляются из системы. Уровень слоя кодируется
**люминансом поверхности + hairline**. В тёмной теме тень физически
бессмысленна (тень от чёрного на чёрном), и её отсутствие читается
дороже.

Исключение ровно одно: primary CTA сохраняет мягкое свечение как
единственный «дорогой» элемент экрана.

### 1.3 Волосяные границы 0.5px

Linear использует границы 0.5px. На дисплеях с DPR ≥ 2 это настоящая
волосяная линия, недостижимая в 1px.

```css
.hairline { border: 1px solid var(--hairline); }
@media (min-resolution: 2dppx) {
  .hairline { border-width: 0.5px; }
}
```

Деталь, которую нельзя осознанно заметить, но которая отличает
«сделано дизайнером» от «сделано разработчиком».

### 1.4 Грейн

Один `::before` на корневом контейнере, инлайновый SVG `feTurbulence`,
непрозрачность 3.5% (нижняя граница нормы 5–15%). Наносится **только
на канвас**, не на каждую карточку — иначе шум складывается на
границах. Убирает эффект «цифровой пустоты» у почти-чёрного фона и
даёт тактильность за три строки CSS.

### 1.5 Типографика

Geist Sans / Geist Mono остаются — они сделаны именно под dev-facing
приложения. Добавляется:

- `opsz` (optical size) через вариативную ось: на 12px буквы
  разряжаются для читаемости, на 36px поджимаются.
- `tabular-nums` **обязательно** на всех колонках чисел.
- Числа, валюта, проценты — выравнивание **вправо**, чтобы цифры
  выстраивались по разрядам. Текст — влево. Это половина ощущения
  «дорого» в data-таблице.

### 1.6 Бюджет движения

Единственное правило: **бюджет обратно пропорционален частоте**.

| Частота действия | Бюджет |
|---|---|
| Сотни раз/день — клавиатура, hover в таблице | 0–100 мс, только `opacity` |
| Десятки раз/день — открытие панели, фильтр | 150–200 мс, `transform` + `opacity` |
| Единицы раз/день — смена раздела | 200–300 мс, View Transition |
| Раз в сессию — вход | здесь и только здесь «дорогой» момент |

Жёсткие правила:

- Длительность < 300 мс почти всегда. Больше — читается как лаг.
- `ease-out` на вход, `ease-in` на выход.
- **Никогда не анимировать действия с клавиатуры.** Cmd+K-палитра,
  навигация стрелками, submit по Enter — открываются мгновенно.
  Именно эта мгновенность читается как «дорого».
- Анимировать только `transform` и `opacity` — они триггерят только
  composite. `width`/`padding` триггерят layout → paint → composite;
  на таблице в 500 строк это разница между 60 fps и слайд-шоу.
- Прерываемость обязательна.
- `prefers-reduced-motion` плюс **собственный тумблер в настройках** —
  системная настройка ОС слишком груба для человека, который хочет
  спокойную панель, но живую систему в остальном.

### 1.7 Wow-приёмы (утверждённый набор)

1. **Морфинг строки в карточку через View Transitions API.**
   `view-transition-name` на строке таблицы и на заголовке детальной
   панели — при клике число физически переезжает из ячейки в заголовок.
   Главный приём: одновременно самый эффектный и самый функциональный,
   потому что сохраняет контекст. ~15 строк CSS.
2. **Лестница поверхностей вместо теней** (1.2).
3. **Hairline 0.5px** (1.3).
4. **Плёночный грейн** (1.4).
5. **Cmd+K с областями видимости**, `cmdk` + Zustand для стека
   областей + TanStack Query для асинхронного поиска. Открывается
   без анимации.
6. **Анимированный конический бордер через `@property --angle`** —
   строго на одном элементе за раз, только карточка с активным
   алертом. В статичном интерфейсе движение становится сигналом,
   который невозможно пропустить.
7. **Переключатель плотности** compact / comfortable / spacious,
   сохраняется в Zustand + localStorage, реализован через CSS-переменную
   `--row-h` — переключение мгновенное, без ререндера.

### 1.8 Data-viz

- Основной ряд — акцент. Сравнительный (прошлый период) — тот же
  оттенок на 35% прозрачности, пунктиром. Третий+ ряд различается
  паттерном и толщиной, **не новым цветом**.
- Цвет вводится только для семантики.
- Гридлайны `oklch(1 0 0 / 0.05)`, только горизонтальные.
- В KPI-плитках — спарклайны без осей и подписей, 30 точек, не 3000.
- **Агрегация на бэкенде.** Recharts рендерит в SVG: 5000 точек =
  5000 DOM-узлов = фриз. График трафика за 30 дней — 30 точек.

### 1.9 Таблицы

TanStack Table + TanStack Virtual (экосистема та же, что у уже
используемого TanStack Query). Порог: после ~1000 строк клиентский
рендер начинает заикаться.

- Sticky-заголовок обязателен, у замороженных краёв — лёгкая тень как
  сигнал слоя.
- Сортировка всегда показывает направление стрелкой.
- Активные фильтры — чипами над таблицей, с количеством результатов и
  кнопкой «сбросить всё». Отфильтрованная таблица, визуально
  неотличимая от неотфильтрованной, — прямая причина неверного чтения
  данных.
- Скелетоны строк **точно той же высоты**, что реальные строки.
- Разные пустые состояния для «ещё нет данных» и «фильтр ничего не
  нашёл» — во втором случае с кнопкой сброса.
- Мобильный: Priority+ для списка (статус + трафик + имя всегда,
  остальное разворачивается) и bottom sheet для деталей вместо
  перехода на отдельный экран — сохраняет контекст списка.
  Тач-таргеты 44px.

## Часть 2. Экран «Пользователи»

### 2.1 Главная проблема

**Экран называется «Пользователи», но списка пользователей в нём нет.**
Единственная точка входа — строка поиска; пока в неё ничего не введено,
экран пуст (`Users.tsx:51`). Нельзя посмотреть «кто зарегистрировался
сегодня», «у кого истекает завтра», «кто с активной подпиской».

REST-эндпоинта листинга на бэкенде тоже нет. Исходные выборки
существуют в `export.py:63` (`get_all_users_for_export`) — нужен новый
`GET /users` с фильтрами, сортировкой и пагинацией.

### 2.2 Баги к починке (приоритет — денежные)

| # | Файл | Проблема |
|---|---|---|

Работает только потому, что React 18 успевает закоммитить стейт до макротаска. При StrictMode/concurrent **вместо списания уйдёт начисление**. ### 2.3 Производительность

- `user_detail` (`users.py:67`) — **8 последовательных `await`**, каждый
  берёт своё соединение; `get_effective_cashback_percent` внутри делает
  ещё 2 запроса. ~11 round-trip на один GET. Фикс: `asyncio.gather` +
  общее соединение.
- Открытие карточки = 3 HTTP-запроса + ~5 запросов внутри
  `extended-stats` = **~20 обращений к БД**.
- `SELECT *` по `users` и `subscriptions` гоняет ~70 колонок, из которых
  UI использует 4.

### 2.4 Типизация

`UserDetail` (`api.ts:95`) имеет три поля типа `Record<string, unknown>`,
что порождает ~25 приведений типов по всему компоненту. Заводим
`types/user.ts` с реальными интерфейсами — это открывает все поля из
2.5 без единого изменения бэкенда.

### 2.5 Новые функции — данные, которые бэкенд уже отдаёт

Из объекта `subscription` приходит ~40 полей, UI использует 2.

| Поле | Ценность |
|---|---|
| `activation_status`, `activation_attempts`, `last_activation_error` | Оплатил — ключ не выдался. Сейчас видно только в `/activations/pending`. |
| `vpn_key`, `vpn_key_plus`, `remnawave_*_sub_url` | Саппорт лезет в БД руками за ключом. |
| `auto_renew`, `last_auto_renewal_at` | «Почему не продлилось?» — ответ в карточке. |
| `last_bytes`, `first_traffic_at`, `activated_at` | Оплатил и не подключался — churn-риск. |
| `source` (`payment`/`admin`/`trial`) | Платящий vs выданный руками. |
| `is_combo`, `is_bypass_only`, `country` | Тип подписки одним взглядом. |
| `admin_grant_days` | Сколько уже надарили бесплатно. |
| `reminder_*_sent`, `smart_notif_*_sent` | Лента коммуникации — что юзеру уже слали. |

Из `user`: `referral_code` (партнёрская ссылка), `referral_level`,
`is_reachable` + `last_seen_at` (заблокировал ли бота — прямо объясняет
`notify_sent: false`), `cashback_floor_percent` (из чего собран
effective), `language`, геймификационный слой (`farm_plots`, `dice_*`).

Из `discount` / `traffic_discount`: `created_by` и `created_at` —
**не видно, какой админ выдал скидку и когда**. Готовый мини-аудит.

**Важно:** `get_subscription` фильтрует только активные. У истёкшего
юзера карточка не показывает ничего о прошлой подписке. Рядом уже есть
`get_subscription_any` — чинится одной строкой в роуте.

### 2.9 Доступность

Иконочные кнопки без `aria-label`, инпуты без `<label htmlFor>`,
таблица без `scope="col"`, результаты поиска без `aria-live`,
спиннеры без `role="status"`, нет фокус-менеджмента при переходе
список → карточка. Нативный `confirm()` для revoke при том, что
удаление VIP и скидки идут вообще без подтверждения — три разных
уровня защиты без логики.
