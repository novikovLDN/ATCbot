# Границы рефакторинга (решения владельца)

Обновлено: 2026-09-13. Документ обязателен для всех, кто работает над аудитом и рефакторингом, включая агентов.

## Цель

**Решение владельца (2026-09-13): бот с нуля НЕ пишем.** Разбираем и упрощаем текущий код поэтапно: чистка, платёжное ядро за флагом, затем слой экранов заново по одному экрану за раз, по скриншотам активных экранов. Схема БД, панель и данные не меняются.

Упростить **всю** систему, а не только платежи. Код большой, и основная его часть пользы не приносит. Убрать всё неиспользуемое и свести логику к простым и понятным модулям. Главный приоритет — корректные и безопасные платежи.

## База и ветки

- Прод = `main`. Работа ведётся в `refactor/audit-2026-09`, это точная копия `origin/main` (`cf8205fc`) плюс наши коммиты.
- **В `main` не мержим** без отдельного решения владельца. Force-push запрещён.
- Дашборд v2 (`atcnew`) синхронизируется с `main` отдельно и тоже не выкатывается.

## 🔒 Магазин — НЕ ТРОГАТЬ

Раздел «Мини-магазинчик» (кнопка `mini_shop`) и всё, что за ним стоит:

| Товар | Код |
|---|---|
| Вход в магазин | `app/handlers/callbacks/navigation.py`: `callback_mini_shop` (`F.data == "mini_shop"`) |
| Telegram Premium | `app/handlers/payments/telegram_premium.py` (`premium_buy`) |
| Telegram Stars | `app/handlers/payments/telegram_stars_purchase.py` (`stars_buy`, кнопка в меню закомментирована) |
| Apple ID | хэндлеры `apple_*` в `navigation.py`, `app/handlers/admin/apple_id_delivery.py` |
| Steam | `app/handlers/payments/steam_purchase.py` (`steam:*`) |
| Spotify | `app/handlers/payments/spotify_purchase.py` (`spotify:*`), `app/handlers/admin/spotify_delivery.py` |
| Claude Pro/Max (скоро) | `claude_coming_soon` в `navigation.py` |
| Тексты | ключи `shop.*` в `app/i18n/{ru,en}.py` |

**Правила:**
- Логику, тексты, цены и UX магазина не меняем.
- Точки, где платёжное ядро вызывает магазин, сохраняем без изменений. В `confirmation.py` покупки магазина (`telegram_premium`, `telegram_stars`, `steam`, `apple_id`, `spotify`) идут через `mark_pending_purchase_paid` + `send_*_success`. Новое ядро обязано вызывать их ровно так же.
- При разбиении `navigation.py` хэндлеры магазина переносятся в отдельный модуль 1:1, построчно, без правок.
- **Единственное допустимое касание:** удаление провайдера Lava (решение владельца) убирает кнопку «Карта (Lava)» с экранов оплаты магазина. Остальные способы оплаты и логика экранов не меняются. Каждое такое место перечисляется в PR.

## Решения по домену

| Тема | Решение |
|---|---|
| Basic / Plus | premium на срок + **10 ГБ bypass один раз** |
| Combo Basic / Combo Plus | **отдельные тарифы**, не «базовый тариф + флаг». Premium на срок + bypass = ГБ из таблицы combo (1 мес = 75 ГБ), без базовых 10 ГБ |
| Пакет ГБ | +N ГБ bypass, premium не трогаем |
| Трафик | ГБ **прибавляются** к остатку |
| Trial | **500 МБ** bypass |
| Двойные начисления | недопустимы: идемпотентность по `purchase_id` |
| Ошибочная транзакция | **любая** → алерт админу в Telegram |
| Lava | не используется, **удаляем полностью** |
| WATA, Platega | действующие провайдеры. Эталон протокола — `docs/providers/*.md` |
| Защита вебхуков для магазина | **магазин как есть**: новые проверки (fail-closed подпись, провайдер и сумма) применяем только к VPN-покупкам. Покупки `telegram_premium`, `telegram_stars`, `steam`, `spotify`, `apple_id_*` проходят прежним путём |
| Рекуррентные подписки Platega | **код удалён** (`9549e706`). Колбэки старых подписок только шлют алерт и пишут `payment_errors`, ничего не выдают. Живые подписки показывает `/platega_sub_status`, отменять их нужно в кабинете Platega |
| Возвраты (`CHARGEBACKED` / WATA Refund) | лог + принудительный алерт админу; доступ автоматически не отзываем |
| Чистка — удаляем | B1 (доки → `docs/archive/`), B2 (мёртвые модули), B3 (хэндлеры-сироты), B4 (Lava целиком; кнопки WATA — гейт на `wata_service.is_enabled()`), B5 (samopis, `vpn_utils`, subscription_proxy), `site_sync` |
| Чистка — оставляем | игра и ферма, sub-aggregator, CryptoBot, Node/Incy (удаляется только мёртвый `selftest`) |
| Выдача днями (админ через дашборд, игра, промо) | **0 ГБ, только premium**. Массовый «бонус» из старой админки удалён (2026-09-14) |
| Автопродление | по тарифу подписки: basic → цена и ГБ basic; combo → **цена combo** и **ГБ combo** |
| Бизнес-тарифы | **удалены** (решение 2026-09-14: «Бизнес удаляем, тарифы и тп не используются»): каталог, меню, экраны, цены, тексты, метки в дашборде. Данные не трогаем: легаси `biz_*` в `subscriptions.subscription_type`, `pending_purchases.tariff`, подарках и `payments.tariff` везде читаются как **Plus** — одно правило `app/services/tariffs.normalize_tier()` (для `payments.tariff` вида `biz_team_30` — `normalize_payment_tariff()` → `plus_30`). Автопродление легаси biz — обычный Plus **по текущей цене Plus**; правило «199 ₽» отменено вместе с biz. Новых проверок `biz` не добавлять |
| Вывод средств | **удалён** (решение 2026-09-14: «Вывод также не используется, удаляем»): кнопки подтверждения у админа, функции БД, счётчик заявок в дашборде, обещания вывода в текстах реферальной программы. Таблица `withdrawal_requests` и история в `balance_transactions` остаются. Пополнение, оплата с баланса и начисление кэшбэка не тронуты |
| Старая админка в боте | **удалена** (решение 2026-09-14: «оставить функцию „написать пользователю“ и ссылку на дашборд, сброс пароля»). Остались: `/admin` (ссылка на дашборд, «💬 Написать пользователю», сброс пароля), чат админ → пользователь (кнопка есть и на алертах заказов магазина), `/platega_sub_status` (в дашборде только счётчики по статусам, без списка живых подписок) и 🔒 выдача заказов Apple ID / Spotify. Всё остальное — веб-дашборд. Кнопки рассылок из дашборда живут в `app/handlers/payments/broadcast_offers.py` |
| Рекуррентные подписки Platega (СБП, `paymentMethod=6`) | **код убираем**. Остаётся только страховка: любой колбэк подписки даёт форс-алерт админу и ничего не выдаёт. Разовые платежи Platega остаются |
| Spotify, оплаченный картой через Telegram | **чиним точечно**: ветка Spotify в `process_successful_payment`, как в вебхуке. Логика, тексты и цены магазина не меняются |
| Чистка — второй круг (решение 2026-09-13: «мёртвый код чистить») | **одобрено:** B6/B7/B9 (неиспользуемые функции БД, Remnawave, прочие), B10 (ruff-автофикс) плюс новый мёртвый код после рефакторинга. Правила: доказательство grep'ом, магазин не трогаем. Порядок: после слияния волны 1 (матрица платежей, контроль доставки, CI) |
| Контроль доставки | после каждой выдачи проверяем панель: срок premium не меньше ожидаемого, лимит bypass равен цели. Расхождение → алерт админу и повтор. Часовой сверки «БД ↔ панель» **нет** (решение 2026-09-13: проверяем каждую выдачу, полный проход по панели не нужен) |
| Длительность тарифов (решение 2026-09-14) | **календарные месяцы**: 1/3/6/12/24 мес. считаются календарными месяцами от конца текущей подписки (до 20 окт. + 1 мес. → до 20 ноя.; конец месяца — последнее число, 31 янв. + 1 мес. → 28/29 фев.). Выдачи днями (админ, игра, промо, бонус) остаются днями. Код: одно правило `app/services/tariffs.extend_expiry` (`grant_access(tariff_period_days=…)`), ключ тарифа — по-прежнему `period_days` 30/90/180/365/730, миграций нет. VPN-бонус покупок магазина (Spotify) остаётся днями — магазин не меняем |
| VIP (решение 2026-09-14) | **удаляем полностью**: статус VIP, VIP-скидка, переключатель в дашборде, тексты. Данные не трогаем (`vip_users` не читается). Партнёрский уровень `referral_level='vip'` — другое, остаётся. Скидки: действует **наибольшая одна** (промокод / спецоффер −15 % / персональная), без суммирования; проигравший промокод не списывается; кнопка «−15 %» при бо́льшей скидке пишет, что остаётся она |
| Смена тарифа (решение 2026-09-14) | поведение не меняем (тариф меняется **сразу**), исправляем текст экрана |
| Пополнение по СБП с наценкой (решение 2026-09-14) | на баланс зачисляется **только сумма без наценки** |
| Реферальный кэшбэк (решение 2026-09-14) | **только за покупку, любую** (подписка, продление, автопродление, комбо, пакет ГБ, подарок; любым способом оплаты, включая баланс); за пополнение баланса — **никогда** |
| Скидка −15 % при окончании подписки (решение 2026-09-14) | нужна, чинится |
| ГБ при продлении (подтверждено 2026-09-14) | Basic/Plus: **+10 ГБ за каждую оплату** (покупка и каждое продление). Combo: ГБ **по таблице Combo для периода** при покупке и каждом продлении (1 мес. = 75 ГБ и т.д.) |
| Устройства (решение 2026-09-14) | **Basic — 10, Plus — 14** (как в текстах); лимит в панели ставится по тарифу |
| Уведомление о кэшбэке (решение 2026-09-14) | пригласившему — **о каждом начислении** |
| Кэшбэк за ферму (решение 2026-09-14) | **не начисляется** (грядка, плёнка и прочие игровые покупки) |
| Покупка ГБ с экрана «🌐 Только обход блокировок» без подписки (решение 2026-09-14) | выдаём **купленные ГБ + 3 дня premium в подарок** (независимо от флага пробного периода). Подарочные 3 дня — **один раз на пользователя** (как пробный период; повторная покупка ГБ без подписки даёт только ГБ); подарок получает любой пользователь **без активной подписки, который ни разу не брал пробный период/подарок** — включая бывших платных клиентов (подтверждено 2026-09-14); дополнительные 500 МБ пробного не начисляются — ГБ те, что купил. По истечении premium ГБ продолжают работать (bypass-сущность отдельная). Дальше пользователь может купить/продлить любой тариф: premium продлевается от текущего момента, ГБ не теряются. Требование владельца: без ошибок назначения (раньше были) — покрыть сквозными тестами на настоящей БД |
| Срок скидки −15 % (решение 2026-09-14, выбор за нами) | **один срок — 72 часа** с момента первого предложения в текущем периоде подписки (напоминание перед окончанием или окончание подписки — что наступит раньше); одна скидка на период; повторное нажатие кнопки срок **не продлевает**; в тексте — точная дата и время окончания (МСК), а не «3 часа»/«7 дней»; бо́льшая действующая скидка не понижается |
| Воронка продаж (одобрено владельцем 2026-09-14) | Три цепочки, срабатывают на новые события с момента выкладки. **Общие правила:** покупка/активация пробного сразу останавливает цепочку; ≤1 сообщения цепочек в день на пользователя; отправка только 10:00–21:00 МСК; `is_reachable=false` не шлём; одна действующая скидка (наибольшая, не суммируется), точный срок в тексте, повторное нажатие не продлевает; тексты редактируются в дашборде. **1. /start без пробного и подписки:** +1ч пробный; +1д пробный (что даёт VPN); +3д пробный или −20% 48ч; +7д −25% на первый месяц 72ч; +30д −30% 7 дней. **2. Пробный закончился, не купил:** сразу −30% 7 дней (есть); +1д «ещё 6 дней»; +6д «завтра сгорит»; +14д −25% 72ч; +30д −30% 7 дней; +90д −40% 7 дней. **3. Платная закончилась, не продлил:** сразу −15% 72ч (есть); +6ч напоминание (та же); +1д «ещё 2 дня»; +3д −20% 72ч; +7д −25% 72ч; +30д −30% 7 дней; +90д −40% 7 дней. **Старая база** — одной рассылкой из дашборда (сегменты), темп 25/с, не цепочками задним числом |
| Теги Remnawave (решение 2026-09-14) | premium-сущность — тег текущего тарифа: `TRIAL`, `BASIC`, `PLUS`, `COMBO_BASIC`, `COMBO_PLUS` (легаси biz → `PLUS`), bypass-сущность — `BYPASS`. Ставится при создании и при каждой смене тарифа (покупка, продление другим тарифом, апгрейд / даунгрейд, пробный → платный, подарок) в том же PATCH, без лишних запросов; выдачи днями (админ, игра, промо) тег не меняют; по истечении остаётся последний тариф. Панель не приняла тег → лог и тот же запрос без тега, покупка проходит. Существующие пользователи — только бэкфиллом по кнопке админа: одобрен для пользователей **с активной подпиской**, только теги, ≤ 2 PATCH/с (дашборд → «Ещё» → «Настройки» → «Теги в панели Remnawave» или `scripts/backfill_remnawave_tags.py`) |
| Трафик-уведомления (решение 2026-09-14) | пороги остатка 50/30/15/10/5/3/1 ГБ, только ниже остатка после последней покупки; одно сообщение за раз (самый низкий пройденный порог), ≥3 ч между сообщениями о трафике; докупка ГБ сбрасывает пороги выше нового остатка; при 0 ГБ текст по ситуации (premium есть / нет) |

## Порядок безопасности

- **Перед фазой:** план в чат, затем «ок» владельца.
- **Перед правкой бизнес-логики:** характеризующие тесты.
- **Мёртвый код:** удаляется только с доказательством (нет импортов, регистраций, вызовов из задач, скриптов, Dockerfile, CI) и по списку, подтверждённому владельцем.
- **Миграции:** только additive; удаление колонок — отдельным релизом.
- **Внимание:** `CLAUDE.md` на main местами неверен. Например, корневой `handlers.py` помечен как мёртвый, но из него импортируется `show_payment_method_selection` на пути `/buy`. Любое «мёртво» проверяем grep'ом, а не по документации.
