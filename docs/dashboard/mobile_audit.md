# Дашборд: аудит на всех устройствах и iOS (2026-09-13)

## v5 — iOS-редизайн (2026-09-14)

Владелец пользуется панелью в основном как PWA на iPhone; уголь + кремовый bento v3 отклонён
(«вырви глаз»). Панель переделана под нативное iOS-приложение (стиль «grouped inset»).

  в «Ещё» и «Настройках». Ключ `admin.theme.v5`: старое «dark» означало угольные плитки, поэтому все начинают с системной.
- iOS-приложение: `viewport-fit=cover`, `env(safe-area-inset-*)`, `100dvh`, два `theme-color` (`#F2F2F7` / `#000000`

  `#F2F2F7` их не видно (это и было замечание прошлого аудита). Остаётся: при ручной теме, отличной от системной,
  статус-бар следует системе — iOS читает его один раз при запуске. Меняется мета — иконку на экране «Домой» нужно
  переустановить, чтобы iOS перечитал её.

### Порядок блоков

**Обзор** (период — сегментный контрол «Сегодня / 7 дней / 30 дней», по умолчанию «Сегодня»):
1. Статус: «Всё в порядке» (онлайн, ноды, время проверки) или только настоящие проблемы — алерты critical/warning
   бэкенда, каждый ведёт на свой экран. Информационные (истекают за 7 дней) — в своём блоке.
2. Деньги: выручка VPN за период, дельта к такому же отрезку, «было», спарклайн по дням; строки «Оплат», ARPPU,
   «Платящие», «Новые платящие»; «Оборот» раскрывает магазин, прокси, игру.
3. Подписчики: платные активные, пробные, новые за период, отток (и продления); «С доступом» раскрывает виды.
4. Истекают за 7 дней: всего / сами / без автопродления, столбики по дням, спишется с балансов, хватит / не хватит.
5. Платежи: конверсия счетов за сутки и строка на каждого провайдера с точкой статуса (в ритме / молчит / выключен /
   мало оплат), конверсией и временем последней оплаты (`/metrics/payments-health`); ошибки платежей за 24 ч.
6. Выдача доступа: одна строка «Всё оплаченное выдано», пока очередь, dead и ожидающие активации — нули.

**Деньги:** выручка → все остальные цифры одним списком (оборот, платящие, средний чек, ARPPU, ARPU, MRR, трафик, Stars)
→ динамика → провайдеры → лента покупок → откуда деньги, продукты → баланс и обязательства → когда покупают → LTV.
**Здоровье:** общий статус → компоненты одним списком (БД, вебхук с признаком «очередь растёт», панель, Redis, пул) →
воркеры (с ошибками сверху, исправные свёрнуты в «Работают нормально») → версия, алерты → платежи → выдача → инструменты.
**Подписчики:** с доступом → кто и почему → истекают за 7 дней → продления → прирост, автопродление → продажи → пробный →
воронка → тарифы. **Панель:** ноды считаются от включённых, выключенные — отдельно.

## iOS: Safari, приложение на экране «Домой», встроенный браузер Telegram

- **Safari**: вход паролем и passkey работают. Cookie `atlas_admin_session` — HttpOnly,
  Secure, SameSite=Lax, same-origin. Magic-link (15 мин) — только для первой настройки
  (`POST /auth/setup`, токен в теле). Защиты не менялись: bootstrap-only magic link,
  rate limit, CSRF по Origin, WS только по cookie, Idempotency-Key.
- **Приложение на экране «Домой» (standalone)**: `viewport-fit=cover`, safe-area отступы у
  шапки, тостов, меню, модалок, экрана входа. `100svh` / `100dvh` вместо `100vh`. Кнопок
  браузера нет, но каждый раздел доступен из шапки или меню «Ещё», у вложенных экранов
  (карточка пользователя, новая рассылка) есть «К списку» / «Назад», а ошибка экрана больше
  не оставляет пустую страницу. Хранилище standalone-приложения на iOS отдельное от Safari:
  войти нужно в самом приложении. Passkey из iCloud Keychain там работает.
- **Встроенный браузер Telegram iOS** (WKWebView): `PublicKeyCredential` там есть, но iOS
  не показывает окно passkey чужим WebView без associated-domains — кнопка Face ID
  молча не работала. Теперь такой браузер определяется (`isInAppBrowser`: нет токена
  `Safari/`, `TelegramWebviewProxy`, UA Telegram/Instagram/VK/FB). Кнопку Face ID
  заменяет пояснение «⋯ → Открыть в Safari» и кнопка «Скопировать адрес дашборда»
  (обычный адрес, не magic-link). Вход паролем и первая настройка по ссылке из `/admin`
  там работают (`after-webview/login__393-15.png`).

**Невозможно исправить со стороны веба:**
- passkey во встроенном браузере Telegram — ограничение iOS. Программно открыть Safari из
  WKWebView нельзя, поэтому только инструкция.
- Сессия не переносится между Safari, приложением на экране «Домой» и WebView Telegram —
  у каждого своё хранилище cookie.
- Цвет статус-бара в iOS-приложении читается один раз при запуске, из
  `apple-mobile-web-app-status-bar-style`. Сейчас это `black-translucent` (контент под
  статус-баром, отступы safe-area есть). В основном виде светлая «стена» даёт белые часы
  на светло-сером фоне — контраст низкий. Переключение темы в приложении это не меняет.
  Вариант `default` дал бы белую полосу над тёмной стеной в светлой теме. Оставлено как
  есть, решение за владельцем.
- Web Push на iOS — только в установленном приложении (iOS 16.4+).
