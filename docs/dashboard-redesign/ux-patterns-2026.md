# UX-приёмы для рабочих админ-панелей: фактура с источниками

Дата: 2026-08-03. Дополнение к `research-2026.md`: тот отвечает на вопрос «как
должно выглядеть», этот — «как должно работать».

Проверено около 30 источников. Где страница не открылась — помечено явно.

## 1. Командная палитра (⌘K) и горячие клавиши

### 1.1 Superhuman — единственный подробный первоисточник по дизайну палитры

[blog.superhuman.com/how-to-build-a-remarkable-command-palette](https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/) (проверено)

Шесть принципов:

- **Один шорткат везде.** «Wherever your user is in your app, they must be able to
  bring up the command palette by using the same shortcut.»
- **Централизация.** «Your command palette must be the one place where users can
  find every command.» Прямо против дробления на ⌘K + ⌘P.
- **Полнота при дешёвом добавлении.** «Make it easy to add these commands from
  anywhere in your codebase.»
- **Нечёткий поиск.** Своя библиотека `command-score`: прощает опечатки
  («lnik» → «link»), плюс синонимы («archive» ведёт на «Mark Done»).
- **Контекст поднимает скор, а не удаляет команду.** «Show and hide commands based
  on what's currently active. But, again, only hide commands that are fully
  irrelevant.»
- **Пять команд в первом экране**, у каждой свой значок — значок несёт функцию
  обучения («teach users what to expect»).

Ранжирование — не только fuzzy-score: базовые веса, множители и отношения
«follow» для принудительного порядка.

### 1.2 GitHub Command Palette — самый сложный публично задокументированный вариант

[docs.github.com/…/github-command-palette](https://docs.github.com/en/get-started/accessibility/github-command-palette) (проверено)

- Открытие `Ctrl+K` / `⌘K`, **альтернативное** `Ctrl+Alt+K` / `⌘⌥K` — чтобы не
  конфликтовать с редактором Markdown, где ⌘K вставляет ссылку. Готовый ответ на
  проблему конфликтов в полях ввода.
- Три режима: навигация, поиск, команды.
- **Префиксы как фильтры внутри одного поля:** `#` — задачи и запросы на слияние,
  `@` — люди и организации, `/` — файлы, `!` — проекты, `>` — командный режим.
- **Скоуп — объект первого класса:** показан слева вверху, фильтрует подсказки.
  `Tab` сужает скоуп, `Backspace` расширяет, `⌘Delete` сбрасывает.
- Правило исполнения: команды над текущей сущностью выполняются на странице,
  высокоуровневые — в скоупе палитры. Это снимает двусмысленность «к чему
  применится действие».

Разрыв по загрузкам — примерно 157-кратный, в основном потому, что cmdk лежит в
основе компонента `Command` в shadcn/ui и тянется транзитивно.

**Риск, который стоит проверить перед продом:** репозиторий `pacocoursey/cmdk`
теперь резолвится в `dip/cmdk` (GitHub API отдаёт 301 на `repositories/514395914`),
при том что пакет на npm остался за прежним автором.

Из README cmdk (проверено):
- «⌘K is a command menu React component that can also be used as an accessible
  combobox.»
- «Accessible? Yes. Labeling, aria attributes, and DOM ordering tested with Voice
  Over and Chrome DevTools.»
- **«Virtualization? No. Good performance up to 2,000–3,000 items, though.»** —
  жёсткая граница. Для панели на 1–3 админов не проблема, если не грузить в
  палитру весь список клиентов.
- Использовалась для командного меню Vercel с 2020 года.

Из README kbar (проверено) — чего нет у cmdk из коробки:
- **Вложенные действия**: «hit backspace to navigate to the previous action».
- **Шорткат и пункт палитры описаны одной структурой**: `shortcut: ["b"]`,
  `keywords: "writing words"`. Это даёт бесплатное обучение (см. 1.4).
- **История с undo/redo на каждое действие.**
- Виртуализированный список: «tens of thousands of actions? No problem.»

**Вывод:** для 1–3 админов — cmdk плюс отдельный хук шорткатов
(`react-hotkeys-hook`, 4 012 780 загрузок в неделю, проверено), потому что cmdk
сознательно не берёт на себя глобальные шорткаты.

### 1.4 NN/g про акселераторы

[nngroup.com/articles/flexibility-efficiency-heuristic](https://www.nngroup.com/articles/flexibility-efficiency-heuristic/) (проверено)

- Акселераторы — «secondary ways of accomplishing the same task that function as
  faster (but typically less obvious) methods».
- **Главный приём обучения:** показывать шорткат рядом с командой. «A novice user
  doesn't have to pay attention to the keyboard shortcut at all, but repeated
  exposure to it supports learning for experienced users.»
- Пример реализации: Photoshop — маленькая накладка при наведении, не занимающая
  места в макете.
- NN/g относит к акселераторам и **массовые действия через чекбоксы** — для нашей
  панели это релевантнее палитры.

### 1.5 Доступность и конфликты — жёсткие требования

**WCAG 2.1, критерий 2.1.4 Character Key Shortcuts (уровень A)** —
[w3.org/WAI/WCAG21/Understanding/character-key-shortcuts](https://www.w3.org/WAI/WCAG21/Understanding/character-key-shortcuts.html) (проверено)

Если шорткат висит на одиночной печатной клавише, обязано выполняться хотя бы
одно из трёх: его можно выключить; его можно переназначить с модификатором; он
активен только когда компонент в фокусе.

Мотивация из спецификации: пользователь голосового ввода, рядом произносят «Hey
Kim» — диктовка слышит `y`, `k`, `m` и выполняет архивирование, переход и
отключение звука. Сценарий реальный.

**Вывод:** одиночные буквы допустимы, но нужен либо тумблер выключения, либо
ограничение областью фокуса. Дешевле всего — фокус, и никогда не вешать
однобуквенные шорткаты на опасные действия.

**WAI-ARIA APG, Developing a Keyboard Interface** —
[w3.org/WAI/ARIA/apg/practices/keyboard-interface](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) (проверено)

- Внутри палитры перемещение стрелками, не табом.
- Не использовать `tabindex` больше нуля — менять порядок в DOM.
- **Roving tabindex**: у активного элемента `0`, у остальных `-1`, плюс явный
  `focus()`. Бонус — браузер сам прокручивает активный пункт в видимую область.
- Предусловие: «Before assigning keyboard shortcuts, it is essential to ensure the
  features and functions to which shortcuts may be assigned are keyboard
  accessible without a keyboard shortcut.» Палитра не заменяет навигацию.
- Нельзя занимать комбинации, зарезервированные ассистивными технологиями:
  `Caps Lock + …`, `Insert + …`, `Scroll Lock + …`, на macOS `Control + Option + …`.

## 2. Опасные действия

### 2.1 NN/g: когда подтверждение, когда отмена

[nngroup.com/articles/confirmation-dialog](https://www.nngroup.com/articles/confirmation-dialog/) (проверено)

1. **Только серьёзные последствия** — «destroying users' work or costing large
   amounts of money».
2. **Не для рутины.** «If you cry wolf too many times, people will stop paying
   attention to the question, and the confirmation dialog will lose its power to
   prevent errors.»
3. **Конкретика вместо «вы уверены?».** «Do not ask 'Are you sure you want to do
   this?'»
4. **Кнопки — действия, не «да/нет»**: «Delete file» / «Keep file».
5. Возможность развернуть детали последствий до подтверждения.
6. **Без предвыбранного «да».**
7. Для особо опасного — нестандартное действие: набрать слово (пример NN/g —
   MailChimp).

Главный вывод статьи: «do go to great lengths to provide undo, because some user
errors will remain despite even the best of confirmation dialogs».

[nngroup.com/articles/user-mistakes](https://www.nngroup.com/articles/user-mistakes/) (проверено): возможность отменить
последнее действие делает ошибку дешёвой и позволяет экспериментировать. И
обратное: при подтверждении на каждый чих люди «instinctively clicking the
highlighted Confirm button».

**Единственная широко известная откалиброванная величина окна отмены:** Gmail
Undo Send — 5, 10, 20 или 30 секунд на выбор
([support.google.com/mail/answer/2819488](https://support.google.com/mail/answer/2819488), проверено).

### 2.2 Smashing Magazine (Vitaly Friedman, 2024) — практическая матрица

[smashingmagazine.com/2024/09/how-manage-dangerous-actions-user-interfaces](https://www.smashingmagazine.com/2024/09/how-manage-dangerous-actions-user-interfaces/) (проверено)

- Модальный диалог — когда последствия серьёзные, **особенно необратимые**.
- Отмена — для обратимого; она **не работает** для удаления аккаунта, юридических
  документов и покупок.
- **Ввод слова для подтверждения**: ConvertKit требует набрать «DO IT», Resend —
  «DELETE». Смысл — сбить автопилот.
- **Искусственная задержка как приём:** Glovo после подтверждения заказа
  показывает полосу прогресса, давая окно на пересмотр до списания. Гибрид отмены
  и подтверждения — применим к возврату денег.
- **Danger Zone:** выделенная секция, описание последствий, дополнительная
  проверка — повторный ввод пароля или второй фактор.
- Метки кнопок: не «Confirm», а «Delete API Key», «Pay $97», «Send Message».

### 2.3 GitHub Danger Zone и официальный гайдлайн Primer

Механика «введите имя репозитория» (по поисковой выдаче; страница настроек
требует аутентификации): секция с красной рамкой → нужно ввести **полное имя вида
`owner/repo`** → кнопка неактивна до точного совпадения.

Три слоя защиты: пространственная изоляция, семантическая (точное имя объекта, а
не просто слово «DELETE» — нельзя перепутать объект) и состояние кнопки.

[primer.style/product/components/confirmation-dialog/guidelines](https://primer.style/product/components/confirmation-dialog/guidelines/) (проверено):
- **Использовать** для разрушительного, необратимого (включая **отправку
  уведомлений** и финализацию транзакций), высокого влияния, потери данных.
- **Не использовать** для легко отменяемого и частого — «this creates fatigue».
- Метки: «action-oriented language, be specific about what will happen, keep
  labels concise (1–3 words)».

Обратите внимание: Primer относит отправку уведомлений к необратимому — массовая
рассылка по этому гайдлайну заслуживает диалога.

### 2.4 Ловушка: отмена в исчезающем тосте ломает доступность

[adrianroselli.com/2020/01/defining-toast-messages.html](https://adrianroselli.com/2020/01/defining-toast-messages.html) (проверено)

Тост с автозакрытием и кнопкой внутри нарушает как минимум:
- **2.2.1 Timing Adjustable (A)** — «if you follow the pattern where they go away
  after a few seconds, then you are in violation»;
- 2.1.1 Keyboard (A) — интерактив без управления фокусом;
- 2.4.3 Focus Order (A) — сообщение в конце DOM недостижимо;
- 1.3.2 Meaningful Sequence (A).

Рекомендация: тост с интерактивом надо «move focus to the container and make it
persistent» — фактически превратить в немодальный диалог.

Дополнение (Sara Soueidan, ARIA Live Regions): живая область должна существовать
в DOM **заранее**; тост, вставленный целиком вместе с `aria-live`, скринридером
не озвучится.

**Вывод для нас:** не исчезающий тост на 5 секунд, а неавтозакрывающийся баннер
в шапке списка, живущий до следующего действия или явного закрытия.

### 2.5 Аудит-след: три эталона

| | GitHub | Stripe Events | Linear |
|---|---|---|---|
| Хранение | **180 дней**, в интерфейсе по умолчанию 3 месяца | **30 дней** через API | **90 дней**, только Enterprise |
| Поля | кто, действие, время, репозиторий, затронутый пользователь, **страна** | тип события и полный снимок объекта в `data` | кто (id, имя, почта), тип, время, **IP и страна**, user agent, метод входа |
| Фильтры | `operation:` (access, authentication, create, modify, remove, restore, transfer), `actor:`, `created:`, `country:`, операторы `-`, `>`, `<` | по типу | по типу и **опция скрыть события создания сессии** |
| Доступ | админы организации | ключ API | **только владельцы** — «given the sensitive nature of the information» |
| Экспорт | — | вебхуки | стриминг в вебхук с подписью, для SIEM |

Что стоит скопировать при 1–3 админах:
1. Семь глаголов-операций как фильтр первого уровня вместо сотни строковых имён.
2. Опция «скрыть шум» — иначе входы забивают ленту.
3. IP, страна и user agent — при малом числе админов это главный сигнал
   компрометации.
4. Снимок объекта в событии — чтобы «кто что сделал» отвечало и на «что было до».
5. Ограничение доступа к самому журналу.

## 3. Состояния: пустое, загрузка, ошибка

### 3.1 Пороги задержки — точные цифры

[nngroup.com/articles/response-times-3-important-limits](https://www.nngroup.com/articles/response-times-3-important-limits/) (проверено)

- **0,1 с** — предел ощущения мгновенной реакции, обратная связь не нужна.
- **1,0 с** — предел непрерывности хода мысли.
- **10 с** — предел удержания внимания; дальше нужен прогресс и возможность
  прервать.

[nngroup.com/articles/progress-indicators](https://www.nngroup.com/articles/progress-indicators/) (проверено)

- Индикатор — для всего, что дольше примерно **1 секунды**.
- **Крутилка — только 2–9 секунд**; от 10 секунд — процент выполнения.
- Статичные индикаторы не использовать.

Готовая лестница:

| Задержка | Что показывать |
|---|---|
| < 0,1 с | ничего |
| 0,1–1 с | мгновенная реакция кнопки |
| 1–2 с | скелетон блока |
| 2–10 с | крутилка и текст, что происходит |
| > 10 с | процент выполнения и кнопка «Прервать» |

### 3.2 Скелетоны — доказательная база противоречива

[viget.com/articles/a-bone-to-pick-with-skeleton-screens](https://www.viget.com/articles/a-bone-to-pick-with-skeleton-screens) (проверено, цифры полные)

Мобильный тест, три варианта одинаковой длительности, n = 136.

| | Воспринятое ожидание, с | «Загрузилось быстро», % | Время задачи, с |
|---|---|---|---|
| Скелетон | **2,82** | **59** | 10,54 |
| Крутилка | 2,41 | 74 | 9,49 |
| Пустой экран | 2,29 | 66 | 9,50 |

Вывод авторов: «skeleton screen performed the worst by all metrics». Гипотезы:
новизна перетягивает внимание; работает лучше в **знакомых** интерфейсах.

Контр-данные (ResearchGate, «The effect of skeleton screens») показывают
обратное, но **полный текст за регистрацией, цифры не проверены**.

**Честный вывод:** для панели, которой пользуются каждый день, работает аргумент
«знакомый интерфейс» — админ знает, что будет на месте прямоугольников. Для
одноразовых экранов скелетон не нужен.

### 3.3 Carbon (IBM) — самая конкретная инструкция

Источник: `raw.githubusercontent.com/carbon-design-system/carbon-website/main/src/pages/patterns/loading-pattern/index.mdx` (проверено; сама страница отдаёт усечённый контент).

- Скелетоны — для **первой загрузки страницы**, «only appear for only a few
  seconds», и обязаны **двигаться**: «use motion to convey that the page is not
  stuck».
- **Можно:** контейнерные компоненты и данные — плитки, списки, таблицы, карточки.
- **Нельзя, дословно:** «Never represent toast notifications, overflow menus,
  dropdown items, modals, and loaders with skeleton states.»
- Кнопкам, полям, чекбоксам и переключателям скелетон **не нужен**.
- Индикатор загрузки ≠ полоса прогресса: если процесс дольше пары секунд — полоса.
- Полноэкранная загрузка — когда действие временно выключает приложение. Если
  процесс займёт больше нескольких минут — вместо блокировки слать уведомление.
- Постепенная загрузка: сначала структура и текст, потом изображения и
  интерактив. И важное: «Not all items need a skeleton state and instead can be
  expressed as negative or white space» — картинку показывать пустым местом, а не
  серым прямоугольником.

### 3.4 Пустые состояния — четыре разных случая

Shopify Polaris (⚠️ прямой запрос по старому адресу даёт 301 → 404; данные из
выдачи по актуальному компонентному адресу):
- Применять, когда в списке, таблице или графике нет данных.
- Компонент рассчитан на **целую пустую страницу**, не на отдельную область.
- Тон: «never make merchants feel unsuccessful or guilty» — не винить.
- Структура: заголовок → поясняющий подзаголовок → кнопка со следующим шагом.

Atlassian (⚠️ оба адреса вернули 404 при запросе; данные вторичные):
- Пустое состояние «describes what the user can do next».
- Может быть и внутри панелей и таблиц, в отличие от Polaris.
- **Отдельный сценарий «нет прав»** с готовым текстом: «You don't have access to
  this issue» и «ask a project admin for permission».

Матрица для нашей панели:

| Случай | Причина | Текст | Действие |
|---|---|---|---|
| Первый запуск | сущностей нет | зачем нужен раздел | «Создать первого клиента» |
| Пустой фильтр | данные есть, фильтр не совпал | назвать фильтр | «Сбросить фильтры» |
| Нет прав | роль не позволяет | без вины, кто выдаст доступ | контакт владельца |
| Отказ виджета | ошибка загрузки | что именно не загрузилось | «Повторить» на месте |

Критично: **не путать пустой фильтр с первым запуском.** Кнопка «создать» на
пустом результате поиска — классическая ошибка.

### 3.5 Ошибки: где показывать

[nngroup.com/articles/error-message-guidelines](https://www.nngroup.com/articles/error-message-guidelines/) (проверено)

- **Рядом с источником ошибки.**
- **Модальное — только для серьёзного**, тост — для мелкого.
- Человеческий язык, без кодов ошибок; вместо «произошла ошибка» — конкретика.
- Тон без обвинения, без слов «неверный»; **юмор не использовать** — приедается.
- Сохранять введённое, чтобы правили, а не набирали заново.

[nngroup.com/articles/indicators-validations-notifications](https://www.nngroup.com/articles/indicators-validations-notifications/) (проверено) — разводка каналов
по трём осям: тип информации, срочность, требуется ли действие.

**Частичный отказ виджета.** Прямого гайдлайна не нашлось. Синтез из правила
«ошибка рядом с источником» и загрузки по месту: отказавший виджет **держит свои
габариты**, внутри краткая причина и кнопка «Повторить», остальная панель не
блокируется. Глобальное сообщение оправдано, только когда отказали все виджеты —
это уже сеть или сессия.

### 3.6 Оптимистичные обновления

Авторитетного гайдлайна уровня NN/g по теме нет — она живёт в инженерных блогах.
Что сходится у нескольких источников:

1. **Не применять к деньгам и разрушительным действиям.** Отзыв доступа, возврат,
   рассылка — без оптимизма, только явное состояние ожидания.
2. Оптимизм — для дешёвого и обратимого: переключатели, переименования.
3. Валидация **до** оптимистичного применения, иначе интерфейс на мгновение
   покажет заведомо невалидное состояние.
4. **Откат обязан быть видимым**: автоматический откат плюс сообщение. Молча —
   нельзя.
5. Кнопку «Повторить» давать **только при временных отказах** (503, таймаут,
   обрыв). При ошибках клиента повтор бессмыслен и вводит в заблуждение.
6. Не выстраивать цепочку оптимизмов на зависимых операциях.

Пункт 4 конфликтует с 2.4: сообщение об откате с кнопкой не должно быть
исчезающим тостом.

## 4. Мобильные рабочие панели

### 4.1 Stripe Dashboard mobile — публичный список «что оставили, что выкинули»

[docs.stripe.com/dashboard/mobile](https://docs.stripe.com/dashboard/mobile) (проверено)

**Оставлено:** метрики и настраиваемые графики, поиск по всему бизнесу, приём
платежей, **возвраты включая частичные**, чеки, клиенты целиком, выплаты,
push-уведомления (дневная сводка, новые платежи, новые клиенты, **оспоренные
платежи**), виджеты на экране блокировки.

**Выкинуто:** только боевой режим — тестовых данных нет вовсе; **управление
спорами отсутствует** — уведомление приходит, действовать нельзя; привязка карты
и счёта только в вебе; роль поддержки **вообще не может войти** в приложение.

**Ключевой приём: уведомить на телефоне, действие увести на десктоп** — для
всего, что требует разбирательства.

### 4.2 Shopify — правило «что нативно, что веб»

[shopify.engineering/building-shopify-mobile-with-native-and-web-technology](https://shopify.engineering/building-shopify-mobile-with-native-and-web-technology) (проверено)

- «Core parts of the app that are used most are native to give the best experience
  on a small screen.»
- Нативно то, что требует интенсивного ввода или высокой плотности информации.
- В веб-вид уходят «several of the settings pages, as well as reports».
- Заявленный выигрыш нативного подхода — «more than 40% more vertical real estate».

Для PWA это переводится так: **настройки и отчёты можно оставить как есть, а
частые операции переверстать под телефон.** Не переверстывать всё.

### 4.3 Linear mobile

⚠️ Первоисточник не найден: `linear.app/docs/command-menu` и
`/docs/keyboard-shortcuts` отдают **404**. Данные из обзоров, доверие среднее.

- На телефоне нет автоматизаций, кастомных полей, роадмапов.
- Редактирование задачи — отдельный диалог с явным сохранением, **без
  редактирования по месту**: сознательное огрубление ради надёжности на тач-экране.
- Позиционирование: всё, что нужно «during a meeting».

Полезная формулировка критерия: мобильная панель обслуживает сценарий **«я не за
столом и что-то происходит»**, а не «я работаю».

### 4.4 PWA на iOS — состояние на 2026

**Web Push** ([webkit.org/blog/13878](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), проверено):
- Появился в iOS 16.4.
- **Только для приложения, добавленного на домашний экран.** Из вкладки Safari не
  работает.
- Разрешение запрашивается **только по прямому жесту** — нельзя дёргать на
  загрузке.
- **Значок на иконке** (`setAppBadge`) работает **даже до получения разрешения** на
  баннеры — лазейка для счётчика.
- Членство в Apple Developer Program не требуется.

**Declarative Web Push** ([webkit.org/blog/16535](https://webkit.org/blog/16535/meet-declarative-web-push/), проверено):
- iOS 18.4 и новее; service worker не обязателен.
- Поле `navigate` обязательно — определяет, куда откроется приложение по тапу.
- ⚠️ Статья не повторяет требование установки на домашний экран, но для iOS оно
  никем не отменялось — считать в силе и проверять на устройстве.

**Установка** ([MDN, Making PWAs installable](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), проверено):
- **`beforeinstallprompt` на iOS не поддерживается** — автоматического «Установить»
  не будет никогда. Нужна своя инструкция «Поделиться → На экран Домой».
- iOS 16.4 и новее — установка из Safari, Chrome, Edge, Firefox, Orion.
- Манифест: имя, иконки 192 и 512, `start_url`, `display: standalone`, HTTPS.

**Безопасные зоны** ([MDN, env()](https://developer.mozilla.org/en-US/docs/Web/CSS/env), проверено):
- `env(safe-area-inset-*)` доступно во всех браузерах с января 2020, работает при
  `viewport-fit=cover`.
- Нижняя панель: `padding-bottom: calc(1em + env(safe-area-inset-bottom, 0px))`.
- Новое: `safe-area-max-inset-*` — статические максимумы, чтобы макет не прыгал.

Недоступно на iOS: фоновая синхронизация, Web Bluetooth и NFC, автоматическое
предложение установки.

### 4.5 Таблицы на мобильном

[nngroup.com/articles/mobile-tables](https://www.nngroup.com/articles/mobile-tables/) (проверено)

- Предусловие: сначала сделать пригодную таблицу для большого экрана.
- **Липкие заголовки** для всего, что длиннее экрана; при горизонтальном скролле
  — фиксировать ещё и левую колонку.
- Дать выбор показываемых колонок.
- **Подсказка горизонтального скролла:** лучше всего стрелки или обрезанный
  элемент. «Dots are sometimes used, but are typically harder for users to notice
  and understand than arrows or cut-off elements.»
- **Сравнение — главная ловушка:** нельзя заставлять переключаться между экранами.

Три канонических паттерна:

| Паттерн | Когда | Что теряется |
|---|---|---|
| Горизонтальный скролл | нужна вся таблица, сравнение по строкам | много жестов |
| Приоритет колонок | 8+ колонок разной важности | скрытое надо искать |
| Карточки | независимые записи | **убивает сравнение по колонкам** |

**Для нас:** список клиентов — карточки (записи независимы), таблица трафика —
горизонтальный скролл с липкой первой колонкой.

## Сводка: что применить

1. **⌘K** на cmdk плюс отдельный хук шорткатов. Одна клавиша везде, `⌘⌥K` для
   полей ввода. Пять команд в первом экране, иконка у каждой. Контекст поднимает
   скор, не прячет. Префиксы `>` и `@` в одном поле. Шорткат рисуется справа — это
   и есть обучение.
2. **Однобуквенные шорткаты** — только при фокусе на компоненте. Никогда на
   опасные действия.
3. **Отзыв доступа** → окно отмены около 30 секунд в **неисчезающем баннере**, не
   в тосте.
4. **Возврат денег** → подтверждение обязательно, кнопка «Вернуть 1 490 ₽», без
   предвыбранного «да», сумма и получатель в теле диалога, без оптимистичного
   обновления.
5. **Массовая рассылка** → гибрид: диалог «Отправить 1 248 получателям» плюс
   отложенный запуск на 60 секунд с возможностью отмены.
6. **Удаление клиента** → ввод **точного идентификатора**, кнопка неактивна до
   совпадения.
7. **Журнал действий**: семь глаголов как фильтр первого уровня, кто и откуда,
   опция «скрыть входы», снимок объекта.
8. **Загрузка** по лестнице из 3.1. Скелетоны только для таблиц, карточек и
   плиток; никогда для модалок, тостов, выпадающих списков и кнопок.
9. **Ошибки** по месту; «Повторить» только при временных отказах; отказавший
   виджет держит габариты и не блокирует панель.
10. **PWA на iOS**: своя инструкция установки, пуш только после установки и только
    по жесту, безопасная зона снизу, значок на иконке работает без разрешения.
11. **Мобильный скоуп**: уведомление на телефон, разбор на десктопе. Клиенты —
    карточки; трафик — горизонтальный скролл со стрелками, не точками.
