## Что сделано в последней сессии

Каждая правка — отдельный коммит с объяснением дефекта в теле сообщения.

**Деньги**
- Выручка считалась 2–3 раза: пополнение баланса → покупка с баланса →
  автопродление. Зафиксировано определение «выручка = внешние поступления»,
  фильтр применён во всех денежных запросах, добавлена миграция 072
  (`payments.payment_provider`), тест проверяет каждый запрос.
- Удаление пользователя стирало payments/pending_purchases/balance_transactions —
  выручка менялась задним числом. Финансовые строки сохраняются, в audit_log
  пишется, сколько их и на какую сумму.
- Оплаченная плёнка от шторма, которая не применилась, не возвращала деньги.
  Теперь возврат на баланс в той же транзакции + понятный текст пользователю.
- Заработанное в мини-играх больше не выводится на карту (`get_balance_breakdown`);
  трата внутри бота гасит игровые деньги первыми.

**Платежи и уведомления**
- Подарок, оплаченный через вебхук, не доставлялся покупателю.
- Забытый тип покупки больше не финализируется как VPN-подписка (предохранитель).
- Реферер не получал уведомления о кешбэке при оплате через вебхук; введён
  общий `notify_referral_cashback`, копипаста из трёх мест удалена.
- Флаги `reminder_7d_sent` / `reminder_1d_sent` не сбрасывались — напоминание
  приходило один раз за всю жизнь. Плюс миграция 071 для текущей базы.
- Автонапоминания уходили на русском независимо от языка пользователя.
- `KeyError('action_type')` в уведомлении о кешбэке у пяти языков.

**Автопродление**
- Весь батч в одной транзакции: ошибка на одном откатывала всех. Теперь
  savepoint на пользователя, Telegram — только после коммита.
- Цена считалась своей формулой мимо `calculate_price` (мимо админских override).
- В уведомлении всегда стояло «списано 0 ₽».

**Дашборд**
- Прямая ссылка и F5 на разделе давали 404 (SPA-фолбэк).
- Событие `payment:approved` не публиковалось: живая лента пустая,
  milestone-push не приходил.
- Тумблеры «Telegram DM» управляли web-push, а DM не отправлялись; добавлен
  запасной канал в Telegram, тексты приведены в соответствие.
- `/stats/overview` не отдавал `business_metrics` — шесть KPI показывали «—».
- На iPhone экран push показывал «не поддерживается, откройте в Safari»
  человеку, который уже в Safari; правильная инструкция была недостижима.

**Игры**
- Ферма не проверяла подписку — middleware на роутере закрывает все `farm_*`.
- Реконсиляция резала оплаченный доступ до суток, когда пересчёт расходился
  с базой в большую сторону.

## Как продолжать

1. Границы блоков при разбивке файлов считать по AST, а не по номерам строк:
   разрез по строкам один раз прошёл посреди функции.
2. После каждого выноса гонять `ruff` — тесты не видят потерянных импортов,
   потому что в них нет доступа к БД.
3. Массовые правки SQL не делать регуляркой с переносом строки: однострочные
   SQL-литералы рвутся, и файл перестаёт парситься. Заменять в пределах строки.
4. Перекрёстные зависимости между новыми модулями — локальными импортами,
   с причиной в комментарии.
5. Каждый новый роутер подключать в `__init__.py` пакета: забытый
   `include_router` не даёт ошибки, кнопки просто молчат.
